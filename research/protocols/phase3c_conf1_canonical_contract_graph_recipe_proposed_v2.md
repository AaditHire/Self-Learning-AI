## 2. The construction function and closed input grammar

Define Recipe_v2(FrozenSlotSpecification) as a symbolic construction function. Its only inputs are the bound authorities, one validated ledger record, and ISOLATED or COMPOSITION only for a training record. It has no source, cases, model outcome, acceptance finding or implementation configuration input. Task/slot IDs are lookup/provenance fields, never dispatch predicates.

A specification has exactly: authority_binding, population_kind, slot_identity, family, frozen_record, condition. The binding identifies every authority above; population_kind is TRAINING, PRIMARY, PRIMITIVE_SANITY or STRUCTURAL_TRANSFER. Family is numeric_iteration or array_reduction. Condition is null for evaluation and one of the two frozen conditions for training. frozen_record has EXACTLY its ledger group's existing fields; validate its full equality to the selected bound ledger record, rather than allowing a caller to supply “equivalent” fields. Reject unknown, omitted, duplicate or altered fields/roles. A record's variant is provenance, not permission to choose another function.

Construction has these fixed stages: validate binding/record; choose the closed semantic term and required role set; lower domain and phases; lower only referenced predicates; lower state/term/output; derive own-target complete-domain output declarations before case acceptance; attach fixed scientific facts; assign positive essentiality and exhaustive atomic/context classification; derive direct prerequisites; assign occurrence and requirement identities; serialize. Any undefined operation, role, attachment, classification, prerequisite owner or intervention destination is a rejecting construction, never an implementation-default choice.

The closed symbolic grammar is:
- values: decoded numeric n, four decoded signed array values, original current index, exact integer constants, and named state views;
- the eight named predicate definitions in §8;
- pure operators neg, add, sub, mul, mod, eq, lt, le, and, or, and BOOL_TO_INT;
- bounded traversal, IF choice, indexing, declaration/binding, initialization, assignment/update and final integer display;
- sum_per_item, strict-prior prefix_pair, and completed product_of_counts, expanded by §§11–15, never graph macros.

Divisor evaluation is permitted only at valid numeric indices 1..n. Types are INT, BOOL, INDICATOR_INT (integer 0/1), TEXT, TEXT4, INT4 and UNIT. INT retains the frozen language/compiler's integer semantics; no new precision, overflow or division convention is supplied. Future compiler/reference incompatibility is FAIL/UNRESOLVED, not a rewritten predicate.

* DOMAIN_VALUE(n) and the four decoded FIELD_VALUE integers are actual domain-value nodes because input identity/domain membership and four original decoded fields are independently meaningful parts of the common typed graph/decoder obligation. No actual BINDING NODE is emitted by this grammar.
* The INT4 decoder package is the ordered tuple reference to the four decoded field nodes. * Named predicate root and its defining comparison root are compatible semantic views of the same actual predicate computation. These are consequential methodology choices, not activity-based switches or claims that coverage will pass. If a future source requires a genuinely new binding, package assembly, TEXT field lookup or carrier operation outside this fixed construction, reject correspondence/STOP for review; do not switch v2 representation to fit that source or activity. ## 5. Identity, occurrence paths and stable order

A graph document has exactly schema_version=2, recipe_version="CONF1_CG_RECIPE_V2", authority_binding, specification_binding, nodes, edges, states, phases, contextual_records, attachments, requirements, prerequisites, complete_function. This is a proposed canonical semantic representation, not a modification of frozen scientific report envelopes or raw source inventories.

Use D §3.3's length-framed RID construction (UTF-8 bytes, no unframed concatenation) with new *representation namespaces* CGNODE, CGEDGE, CGSTATE, CGPHASE, CGATTACH, CGCONTEXT, CGPREREQ, CGREQ and CGKEY. These are IDs, not scientific categories or report-row families. The framing is an exact ID string, not an implementation-selected digest of that string. Let B be the bound atomic/activity/output-freeze SHA-256 and V be CONF1_CG_RECIPE_V2. The specification provenance tuple is population_kind, slot_identity, family, condition-or-the-literal-NONE. CGNODE/CGEDGE/CGSTATE/CGPHASE/CGCONTEXT use, in that order, V, B, the four provenance components, and the canonical JSON of their tagged occurrence path. CGATTACH uses V, B, the same provenance, owner occurrence ID, kind, port-or-NONE, and canonical JSON of semantic_role/value/referenced_occurrence_ids in schema order. CGREQ uses V, B, the same provenance, selected occurrence ID and decimal selector-profile ordinal. CGKEY uses V and canonical JSON of the key projection in §20's stated field order; it omits B, program/task/condition IDs and occurrence provenance. Authority binding remains mandatory outside the reusable key. No alternative hash/truncation/delimiter is permitted, and none redefines D's scientific row IDs.

occurrence_path is an array of closed role labels and nonnegative integers: domain; traversal ordinal; stage; semantic role; expression operand path; repeated-use ordinal. Clause-local ordinals are generated from frozen term positions and port roles. They never depend on dictionary/source traversal. Each component is tagged as LABEL or ORDINAL; absent phase membership is represented by ordinal 0 and traversal j by ordinal j+1. Labels are generated only from the closed clause/role/operation names and expression-port paths stated here, never caller text. Label strings compare by exact UTF-8 bytes; integers compare numerically; LABEL sorts before ORDINAL. Clause-generated repeated-use ordinals start at 0 and count distinct formal uses in left-to-right term/port order. For an operator tree, operand paths are its arity-preserving preorder positions after the permitted local child normalization, with equal children tied by original term position. For a shared producer use, record the consumer term/operand position rather than emitting another producer. For state-view facts use INITIAL, PRE, POST, COMPLETED in that fixed order (current INDICATOR reads use PRE at their term stage); actual read nodes are only those specified in §3; state ordering is phase ordinal, then the closed role order INDEX, INDICATOR, TOTAL, PRIOR_P_COUNT, P_COUNT, Q_COUNT, FINAL_RESULT, with indicators ordered by their Boolean-term paths. Phase paths contain their traversal ordinal.
