# CONF1 prospective task-essential coverage method, recovery v1

This method is frozen before attempt 004 is constructed. Apply it to all 120 training examples and all 64 evaluation tasks. The machine report must contain one row per item and one requirement record per capability. An incomplete report is a failure, never a PASS.

## Classification

`TASK_ESSENTIAL` means the task specification and expected-value function require a capability for a correct solution, independent of the canonical reference's spelling. `REFERENCE_ONLY` means a concrete source choice can be replaced by a semantically equivalent covered expression or control structure without changing any input/output behavior; the report must name that equivalence. A task-essential capability missing from either training condition is a STOP. A task's entire novel composition graph or Structural Transfer arrangement is a withheld **signature**, not an atomic primitive capability; it is audited separately for full-signature absence. This boundary cannot be moved after seeing candidate data.

Every row must inventory these categories, including empty categories: (1) named semantic predicates and their exact operand kinds; (2) GOCO declarations, indexing, input, loop, conditional, and display constructs; (3) namespaced APIs; (4) numeric and string literals and their semantic roles; (5) output values and zero/positive/multiplicity capability; (6) forward/reverse iteration, active branches, and loop carry; (7) arithmetic, comparison, and Boolean operations; (8) atomic dataflow edges and aggregation operators. A reference token not listed as essential must appear in `REFERENCE_ONLY` with a reason. Variables' incidental names, whitespace and parentheses used only for precedence are reference-only. Parser delimiters and array length four are essential to the fixed input schema. The values 0, 1, 2, 3, 4, each offset, modulo base, threshold and array index are inventoried by **role**; a numeric magnitude is essential only where changing it changes the specified function. Source-only spelling of an equivalent constant is reference-only.

Atomic dataflow capabilities are: per-item predicate evaluation into an indicator; resetting an indicator per item; conditional indicator assignment; loop-carried numeric accumulation; addition of a variable or constant into an accumulator; multiplication of two numeric values; using a prior loop-carried numeric value; emitting an expression of accumulated values. The exact multi-edge topology of a graph, ordered pair, or count product is a signature and may be withheld; every component edge and operator must nevertheless be covered in both conditions. A two-pass reference is reference-only if the specification has a one-pass equivalent using covered atomic capabilities. The audit must document that equivalent rather than silently omit the construct.

## Representation test

Build independent capability indexes from the original 60 ISOLATED and 60 COMPOSITION references and cases, separately for numeric and array subskills. A semantic predicate is represented only if the same predicate expression and input role occur in a training target and the five frozen cases for at least one such example include both true and false evaluations on loop items. A GOCO construct, API, operator, or atomic dataflow edge is represented only if it occurs in an executable target path, is semantically active (not dead padding), and the target/cases exercise the path. An essential literal role is represented only if the same role occurs in a training predicate or active scaffold, or a behaviorally equivalent derivation is explicitly recorded with an exact arithmetic witness. Output capabilities require training cases whose expected outputs exhibit the category (zero, positive, at least two, and multi-digit where required). For each evaluation requirement, report evidence IDs in **both** condition indexes; `missing` if either lacks evidence. Do not infer coverage from one condition, an incidental reference token, or a prompt word alone.

Training examples are audited by the same inventory and each must be internally validated against its own five cases. The treatment expressions are classified `INTENDED_TREATMENT_DIFFERENCE`; their separate-versus-joint relation is not required to occur in both conditions. All other atomic capabilities in either training condition must be present in both. All 64 evaluation rows must pass every required category. Summary counts must state 120/120 training rows inventoried, 64/64 evaluation rows inventoried, total essential requirements, per-condition covered/missing totals, and reference-only counts. Any missing requirement yields `STOP_CONF1_COVERAGE_FAILED`.

No future candidate may revise this definition, weaken the representation test, or reclassify a missing capability after seeing attempt-004 results. Such a change requires independent design review before another construction attempt.
