# Proposed CONF1 paired-scaffold normalization clarification

**Status: PROPOSED FOR INDEPENDENT REVIEW; NOT FROZEN OR IMPLEMENTED.** This is a prospective clarification of the paired-condition fairness comparison in `phase3c_conf1_proposed_protocol.md` §§6 and 12, drafted after a prefreeze methodology review found that §12 refers to a frozen identifier/literal-normalization rule without defining one for this comparison. It becomes operative only after independent review and a separate prospective freeze. It does not authorize candidate construction or model execution.

This proposal precedes Attempt 004 and any CONF1 model training or inference. It uses no CONF1 model output or outcome to select a rule. Attempts 001–003 and their stopped/rejected evidence retain their historical interpretation; this proposal does not turn any of them into a confirmatory candidate or retroactively rerun an audit. It applies only to future Attempt 004 or successor candidates built under this CONF1 design, if independently accepted before their construction. The original protocol, slot ledger, AST rules, Coverage v3 proposal, tasks, cases, seeds, budgets, and thresholds are unchanged by this document.

## Scope and source precedence

The authority being clarified is the §12 allowed-difference table: `MATCHED` means zero condition difference; only the marked source treatment expression and marked prompt treatment description are `INTENDED_TREATMENT_DIFFERENCE`; only their mechanically resulting outputs and target serialization may be `UNAVOIDABLE_SEMANTIC_CONSEQUENCE`. A difference outside those classes is `INVALID_UNCONTROLLED_DIFFERENCE` and blocks a future freeze. The §6 indicator scaffold fixes the pair of expressions as independent `hitP+hitQ` versus joint `hitP*hitQ`. The prospective GOCO source correction permits the corresponding parenthesized compound assignments `total+=(hitP+hitQ).` and `total+=(hitP*hitQ).`; the parentheses do not create another treatment difference.

**Prospective procedural amendment, if independently approved:** for this paired-condition audit only, replace §12's instruction to “normalize identifiers and literals according to a frozen rule” with the closed rule below: normalize nonsemantic user-identifier spelling and source whitespace/comments only, then compare the parsed AST; compare every literal token outside the marked treatment subtree exactly, without magnitude placeholders or computed-value folding. Redundant expression parentheses may differ only if ordinary parsing under the pinned grammar produces exactly the same AST, without a separate algebraic or grouping rewrite. The §12 allowed-difference table, including its requirement for the same literals and `k`, remains controlling. This expressly changes the unresolved procedural wording for future candidates; it does not assert that the original sentence already had this meaning.

This is **only** the within-slot ISOLATED/COMPOSITION fairness audit. AST-v2 replaces numeric magnitudes with placeholders **for candidate-versus-consumed template-reuse adjudication**; that normalization does not apply here. Coverage v2/v3 computed-value or semantic-equivalence rules address capability coverage, not paired-scaffold identity, and do not apply here. No similarity score, semantic equivalence assertion, alternative reference, or human waiver can change this comparison.

## Closed prospective comparison rule

1. Pair records by the same frozen `training_paired_slots` slot ID, requiring exactly one ISOLATED and one COMPOSITION record. Before any normalization, require identical domain and input schema, predicate-role assignment and definitions, `k`, loop orientation, ordered case IDs, and exact case-input strings. The expected output is the only case field allowed to differ, subject to the mechanical rule below. A missing, duplicate, unknown, or inconsistent paired slot fails.
2. Parse both GOCO targets with the pinned compiler grammar. Identify the sole marked expression at the specified accumulator update from the frozen scaffold and source-to-slot mapping, not by a free-form text search. Require ISOLATED's expression to be `hitP+hitQ` and COMPOSITION's to be `hitP*hitQ` on the same indicator roles; their necessary GOCO grouping parentheses may be present symmetrically. Replace **only these expression subtrees** by `<TREATMENT_EXPRESSION>` for the scaffold comparison. Any other changed source node remains visible and fails.
3. Identify the one prospectively marked treatment-description clause in each paired prompt using the frozen prompt construction rule. It must request separate counts in ISOLATED and overlap counts in COMPOSITION for the same predicate roles. Replace **only that clause** by `<TREATMENT_DESCRIPTION>`. The rest of each prompt and its model-facing wrapper must be identical, including punctuation and whitespace; prompt text is not alpha-renamed or cosmetically rewritten. An absent, repeated, moved, or extra treatment clause fails.
4. The only source normalization after treatment replacement is (a) consistent, bijective alpha-renaming of user-defined identifiers while preserving declaration/use bindings, repeated identity, types, input roles, indicator roles, accumulator role, and output references, and (b) whitespace and comments that leave the pinned grammar's token sequence and parse unchanged. No separate grouping rewrite is allowed. Redundant expression parentheses may differ only if ordinary parsing under the pinned grammar discards them and yields **exactly the same** complete operator AST, precedence, bindings, source-to-slot mapping, and evaluation order; if the parser retains them in the compared AST or cannot establish identity, the difference fails. A block delimiter, statement delimiter, index operation, or function-call argument grouping is never treated as incidental. Library/API names, GOCO keywords, and numeric/string literal tokens are not user identifiers for alpha-renaming.
5. Compare the normalized, treatment-abstracted parsed sources for exact equality of the complete remaining tree and require exact agreement of the §12 audited feature counts. Also compare every protected slot/case/prompt field in steps 1 and 3 independently, so normalization of source presentation cannot conceal a data or prompt difference. An unknown source form, ambiguous treatment span, failed parse, missing comparison, or uncertain normalization proof fails. There are no candidate-specific exceptions or post-result changes to this rule.

The following are **protected and must not be normalized away**: numeric literal values or spellings; semantic predicate definitions, constants and thresholds; predicate role assignments; library/API identity; input domain and range; actual paired case inputs; `k`; loop bounds, direction and index behavior; semantically meaningful array indices; initialization values; accumulator updates and state; control/dataflow and branch order; output command or expression structure; and every arithmetic, Boolean, comparison, assignment or indexing operator outside the marked treatment expression. Every additional prompt-content or formatting difference outside the marked treatment clause is protected. A difference in any protected field is `INVALID_UNCONTROLLED_DIFFERENCE`, **not** a normalization opportunity. In particular, a value-preserving rewrite such as `1+1` for `2` outside treatment fails the paired-scaffold comparison even if a separate coverage audit considers those computed values equivalent.

## Prospective reading of the §6 normalization phrase

The historical §6 sentence mentions normalizing “IDs, predicate spellings, input values, and `k`” but does not specify whether that list concerns within-slot paired fairness or a generic scaffold comparison across different slots. This document makes a **new prospective choice**, not a claim about its unstated original intent. For within-slot fairness, only nonsemantic user-identifier spelling may be alpha-normalized. Predicate expressions and their literal spellings must be identical between conditions after that identifier normalization; input strings and `k` must be exactly identical. None of these three fields may be replaced by placeholders to excuse a condition difference.

The semantic ledger lists different predicate-role assignments and offsets in different `training_paired_slots`, while §6 defines both conditions for each matched predicate pair and offset and §12 demands the same predicate spellings, `k`, and case-input pairing within that pair. A generic display or comparison **across** different slots may abstract slot-specific predicates, input instances or offsets to describe the shared scaffold; that descriptive abstraction is not evidence that two conditions within one slot are matched and cannot override this fairness rule. Whether the original §6 author intended that cross-slot reading remains unverified.

## Output consequences and parity

For each paired case, compute both expected outputs from the **same** frozen input, predicate definitions, role assignment, initialization and traversal, changing only the marked `hitP+hitQ` versus `hitP*hitQ` expression. A differing expected output qualifies as `UNAVOIDABLE_SEMANTIC_CONSEQUENCE` only if it equals that mechanical derivation; equal outputs on some cases are permitted. The output schema, command, displayed expression and newline remain matched. Target source/text serialization may differ only because the marked treatment expression differs, and serialized output fields may differ only by the derived expected value. Token-boundary changes directly caused by serializing that expression/value are allowed; no independent source, prompt or case-content change is allowed under this label. The original supervised-target difference ≤2%, full-token difference ≤5%, and 320-token no-truncation limits still apply on exact chat serialization. No filler or other source change may be used to satisfy parity.

## Closed threat examples

Each example assumes the same matched slot and a correctly marked treatment expression/description unless the row says otherwise. These are specification examples, **not** new synthetic fixtures or candidate data.

| Proposed difference | Required paired-fairness classification |
|---|---|
| Predicate threshold `i%3==2` changed to `i%3==1` in one condition | `INVALID_UNCONTROLLED_DIFFERENCE`: numeric predicate literal and definition changed. |
| Predicate expression changed while retaining its display name | `INVALID_UNCONTROLLED_DIFFERENCE`: definition changed. |
| One condition changes a case's input string | `INVALID_UNCONTROLLED_DIFFERENCE`: paired case input changed. |
| One condition changes `NUMBER total=k` to a different numeric `k` | `INVALID_UNCONTROLLED_DIFFERENCE`: offset and initialization changed. |
| An extra `IF` guard appears | `INVALID_UNCONTROLLED_DIFFERENCE`: extra control path. |
| An extra loop appears | `INVALID_UNCONTROLLED_DIFFERENCE`: loop structure changed. |
| `strings.TO_NUMBER` is replaced by another API or a call is added | `INVALID_UNCONTROLLED_DIFFERENCE`: API identity/count changed. |
| An accumulator starts at a different value, even with identical later arithmetic | `INVALID_UNCONTROLLED_DIFFERENCE`: initialization changed. |
| `total+=x` outside the treatment slot becomes `total-=x`, or another outside operator changes | `INVALID_UNCONTROLLED_DIFFERENCE`: arithmetic/dataflow changed. |
| Prompt wording outside the marked treatment clause changes, including punctuation or spacing | `INVALID_UNCONTROLLED_DIFFERENCE`: wrapper changed. |
| User variable `hitP` is consistently renamed to `leftHit`, preserving all bindings and roles | `MATCHED` after permitted alpha-renaming. |
| Source whitespace or a comment changes without changing grammar tokens or parse | `MATCHED` after permitted source-format normalization. |
| The sole marked `hitP+hitQ` expression is replaced by `hitP*hitQ` in the other condition | `INTENDED_TREATMENT_DIFFERENCE`; the abstracted surrounding source must still match. |
| The sole marked separate-count prompt clause becomes the joint-count clause | `INTENDED_TREATMENT_DIFFERENCE`; the remaining prompt must still match exactly. |
| Expected outputs differ exactly as mechanically recomputed from the same case and the two treatment expressions | `UNAVOIDABLE_SEMANTIC_CONSEQUENCE`; output schema and parity limits remain unchanged. |

## Relationship to proposed Coverage v3 and review boundary

V3.6 and E3 already require the same marked treatment slots, paired case-input and surrounding-scaffold identity, reject literal/predicate normalization, and limit semantic consequences to mechanically derived outputs and treatment serialization. This proposal supplies the missing prospective scope and closed proof conditions for the older protocol's “normalize identifiers and literals according to a frozen rule” sentence. It does not alter Coverage v3's atomic-coverage, activity, novelty or delegated-evidence gates. A reviewer should decide whether this clarification and V3.6/E3 agree sufficiently; the existence of this proposal alone is not approval or freeze. If independent review finds a remaining textual incompatibility, the documents must be resolved prospectively before candidate construction, without interpreting the conflict from candidate or model outcomes.
