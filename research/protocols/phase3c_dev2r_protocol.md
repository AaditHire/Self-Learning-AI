# Phase 3C-DEV2R evaluation recovery: frozen proposal

**Status:** design frozen before DEV2R model inference; independent review required. The original DEV2 development suite is permanently `CONSUMED_FROM_ATTEMPTED_USE`. Its first unsaved generation and case outcomes are unavailable and are not DEV2R outcomes. This protocol authorizes no model execution, B stage, replay, retention experiment, or final-paper holdout access.

## Root cause and impact

The original evaluator loaded the frozen DEV2 development task row directly, and that schema has no `difficulty`. `score_source` compiled and compared all five cases, then accessed `task["difficulty"]` when constructing `ScoreSummary`. The key lookup raised `KeyError` before the evaluator appended a record or wrote its checkpoint. The retained incident records exception type, message, task, and stage; it does not contain a full traceback or the raw generation. The code path identifies the lookup exactly.

`difficulty` is absent from the prompt template, tokenizer input, model generation, compiler call, expected-output comparison, structural-requirement check, and pass-count computation. It is score metadata, but its missing value prevented score serialization and caused loss of the unsaved scientific observation. The executed cases cannot be reconstructed. No claim is made about whether that first task passed.

DEV2R uses a new evaluator. It validates the task and five cases before generation and supplies the constant `phase3c_dev2r_development` when `difficulty` is absent. The original task metadata is preserved verbatim in the raw record. The frozen `score_source` and compiler remain unchanged. Synthetic regression tests reproduce the old error after five compiler calls, exercise pass and semantic fail, malformed schema, reporting failure, and scoring failure.

## Fresh suite construction

The deterministic builder uses only the frozen DEV2 primitive definitions and input APIs. It does not load adapter generations, prior DEV2 evaluation outcomes, or the final-paper holdout. All tasks are new development tasks. There are 24 numeric-iteration and 24 array-reduction tasks; each subskill has eight Primitive Sanity, eight Novel Composition, and eight Structural Transfer tasks. Each task has five frozen semantic cases, for **48 references and 240 cases**. The original DEV2 audit's 840 cases included training references and therefore is not the applicable DEV2R count.

Primitive Sanity tests the first and last matching position for each of the four common predicates per subskill, with -1 when absent. Novel Composition uses two covered predicate intersections combined as a **union counted once per item**, rather than the original DEV2 evaluation's sum of two intersections. Two fixed predicate pairings and four additive constants per subskill yield eight tasks. Both original training conditions contain all four primitives, but neither contains these full union signatures. Structural Transfer finds a first or last anchor matching one covered predicate, then makes a separate traversal that counts another covered predicate in the anchored suffix or prefix. Both primitives and input APIs occur in both original training conditions; the data-dependent second pass is absent from their training compositions. Four fixed constants per anchor family yield eight tasks per subskill. Constants create correlated variants, not independent archetypes.

The new suite has no exact prompt or reference reuse against the original DEV2 development suite, Phase 3C EVAL_A, DEV1 development, Phase 3A/B A evaluations, or either DEV2 training condition. The audit enumerates all 48×60×2 = 5,760 training pairs, with prompt Jaccard, normalized reference-code similarity, exact prompt/reference flags, and AST-proxy equality. It records nearest neighbors and all lower-threshold pairs, including those below 0.98. Semantic-primitive coverage, composition signature absence, and API requirements are frozen per task. The pinned GOCO compiler validates every reference and all five semantic cases before inference. Similarity metrics are descriptive proxies; they cannot prove distributional independence.

## Limits and STOP logic

This is a development-only recovery measurement of the existing A-only adapters. Training preceded construction of this suite, but human choices during construction can still bias difficulty. Primitive/API coverage and signature novelty are bounded audits, not proof of equal semantic difficulty. Small seed and archetype counts, correlated constant variants, the frozen 2.70% full-token training imbalance, and different ISOLATED/COMPOSITION target semantics limit causal interpretation. A single five-case task pass is not broad capability mastery. Even a positive primary difference would not establish retention, replay benefit, or confirmatory scientific success.

**Design PASS:** six hashes match records and preservation inventory; all 48 IDs and five cases each are unique and frozen; both-condition coverage and union-signature novelty hold; prohibited exact reuse is zero; 48/48 references and 240/240 cases pass; synthetic evaluator tests pass; manifest hashes match. **Design FAIL/STOP:** any mismatch or failed validation. **Future execution STOP:** any missing hash, duplicate output, attempted retry, incomplete raw/primary checkpoint, or evaluator defect requires an incident record and independent review before further model use. Do not reinterpret the consumed original DEV2 attempt. Do not touch the sealed final-paper holdout.
