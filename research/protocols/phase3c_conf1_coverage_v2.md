# CONF1 task-essential coverage v2 — normative specification

**Status:** prospective tooling rule, frozen before implementation and before any attempt-004 construction. This rule does not modify the reviewed CONF1 hypothesis, treatment, endpoints, budgets, or withheld-graph test. It replaces the incomplete coverage *method* for future independent review; no candidate is approved by this document.

## 1. Input contract and extraction boundary

Every future training example and evaluation task must carry a `CoverageContractV2` generated by the prospective builder from the frozen semantic slot ledger, before source/case acceptance. The auditor takes the contract, canonical GOCO source, five semantic cases, and condition label. A missing field, unknown operation, invalid compiler result, or incomplete witness is a **FAIL**, never a default PASS. The contract is a machine-readable specification, not an audit result or a manually curated capability list.

Required fields are `domain`, `predicate_definitions`, `aggregation`, `output_domain`, `source`, `cases`, and `task_kind`. `domain` is `numeric_iteration` or `array_reduction`; numeric input yields positions `1..n`, array input yields four signed values with indices `0..3`. Predicate definitions are named, typed expression trees over `n`, `i`, and `value` with nodes `integer`, `variable`, unary `neg`, binary `add/sub/mul/mod`, and comparisons `eq/ne/lt/le/gt/ge`. Aggregation is one of: `sum_per_item(expression, initial_value)`, `prefix_pair(P,Q)`, or `product_of_counts(P,Q)`. Per-item expressions use predicate leaves, integer constants, arithmetic `add/mul`, Boolean `and/or/not`, and `indicator` (Boolean to 0/1). All nodes and edges are ordered in the contract. `output_domain` declares `integer`, an exact required sentinel set, and whether negative outputs are possible. The auditor interprets the contract on all frozen cases and requires exact agreement with each expected output, then executes the GOCO source with the pinned compiler on those same cases and requires exact agreement. This prevents a contract divorced from its source/cases from supplying coverage.

Machine schema: an expression node is `{"op":"const","value":integer}`, `{"op":"var","name":"n|i|value"}`, `{"op":"pred","name":string}`, `{"op":"neg|not|indicator","arg":node}`, or `{"op":"add|sub|mul|mod|eq|ne|lt|le|gt|ge|and|or","args":[node,node]}`. Aggregation uses `{"kind":"sum_per_item","expr":node,"initial":node}`, `{"kind":"prefix_pair","p":name,"q":name}`, or `{"kind":"product_of_counts","p":name,"q":name}`. `cases` contains five `{case_id,stdin,expected_stdout}` records. `task_kind` is `primary`, `secondary`, or `training`. `output_domain` is `{required_categories:["ZERO"|"POSITIVE"|"NEGATIVE"|"MULTIDIGIT"], exact_sentinels:[integer]}`. `source` is the literal GOCO program. Training records additionally carry `condition` (`isolated` or `composition`); evaluation records carry no condition. Unknown keys or missing required keys are schema errors. The only predicate names permitted in a task expression are those declared in that task's predicate dictionary. Numeric case stdin is one nonnegative integer; array case stdin is exactly four signed decimal integers separated by `|`.

The builder must derive contracts from the immutable slot grammar: named predicate definitions, role-to-predicate mapping, one of the three aggregators, and the graph expression tree. The auditor refuses task-specific free-form capability claims. The same extraction algorithm applies to training and evaluation; neither task IDs, attempt IDs, nor graph IDs are branches in the auditor.

## 2. Closed ontology and rule types

Each emitted requirement has `category`, `canonical_key`, `classification`, `rule_type`, `activity_witness`, and per-condition evidence IDs. The following table is exhaustive for this design. Source-only tokens not represented by a contract requirement are inventoried as `REFERENCE_ONLY` with an allowed proof code; unclassified tokens fail.

| Category | Extracted capability | Canonical representation | Rule type | Training evidence |
|---|---|---|---|---|
| `SEMANTIC_PRIMITIVE` | Each predicate leaf used by aggregation | domain + name + normalized typed predicate tree | `SEMANTIC_EQUIVALENCE_CLASS` | Same key in active training contract of same domain; source/cases validate |
| `LANGUAGE_CONSTRUCT` | input, bounded iteration, conditional choice, numeric assignment/update, final display; array indexing when domain requires it | closed construct key, independent of variable names | `STRUCTURAL_RELATION` | Active contract relation and GOCO source construct certificate; conditional choice can be IF or 0/1 indicator arithmetic |
| `API_CAPABILITY` | Domain decoder: numeric `INPUT`; array `INPUT`, `strings.SPLIT`, `strings.TO_NUMBER` | exact API/library name and input role | `EXACT_SYNTACTIC` | Required parser-chain call in source, validated source/cases, distinct-input witness; a dead extra call cannot satisfy a contract decoder requirement |
| `OPERATOR_CAPABILITY` | Typed predicate and aggregation operators | operation plus operand/result types; comparison direction canonicalized | `SEMANTIC_EQUIVALENCE_CLASS` | Same active operator class in both conditions, except the exact pair-joint treatment relation |
| `LITERAL_OR_VALUE_CAPABILITY` | Exact literal token only if explicitly mandated by task syntax; otherwise computed constant role, input domain, and output categories | separate `LITERAL_TOKEN`, `COMPUTED_VALUE:<integer>:<role>`, `INPUT_DOMAIN`, `OUTPUT_ZERO/POSITIVE/NEGATIVE/MULTIDIGIT`, exact sentinel | `EXACT_SYNTACTIC` or `VALUE_DOMAIN_CAPABILITY` | Active contract constant expression with same value and role, or required expected-output case; syntax-only literal never substitutes for value ability |
| `CONTROL_FLOW_CAPABILITY` | bounded traversal, predicate-conditioned effect, independent checks, nested/dependent branch relation | ordered branch/dependency graph; independent means neither predicate truth depends on the other's result | `STRUCTURAL_RELATION` | Same active local branch relation in source-backed contract; generic IF token alone is insufficient |
| `DATAFLOW_OR_AGGREGATION_CAPABILITY` | predicate→indicator, indicator→numeric operator, numeric→accumulator, loop carry, accumulator→display, sum, product, prior-state edge | typed directed edge or operator node; multiplicity retained | `STRUCTURAL_RELATION` | Same active one-edge capability and operator in both; any multi-edge relation not in the closed atomic list is a withheld signature and is reported separately, not silently covered |
| `STRUCTURAL_SIGNATURE` | Complete per-item truth/contribution vector together with aggregator kind, predicate-sharing pattern, multiplicity and role graph | exact vector for all Boolean assignments in sorted semantic-predicate order plus aggregate and typed edge graph | `STRUCTURAL_RELATION` | Primary full signature must be **absent** in both training sets; local pair motifs are reported separately |

No exact output value is inferred from incidental numeric source spelling. For `OUTPUT_NEGATIVE`, a training expected output below zero is required; for `OUTPUT_ZERO`, exactly zero; for `OUTPUT_POSITIVE`, above zero; for `OUTPUT_MULTIDIGIT`, absolute value at least 10. Exact sentinel values require an output case with that value. A numeric task's required output categories are derived from its declared output domain **and witnessed by its cases**. If a declared possible category lacks a frozen case, the task fails case completeness before coverage.

## 3. Canonical equivalence catalog (closed)

Identifiers may be consistently alpha-renamed. Typed integer constant trees made solely of `integer`, `neg`, `add`, `sub`, and `mul` are evaluated with exact integers; thus literal `-1`, `0-1`, and `(-1)*1` represent the same **computed value**. They do not provide the same literal-token coverage. Commutative pure `add`, `mul`, `and`, and `or` children are sorted by canonical subtree; duplicate children remain duplicated, preserving multiplicity. Boolean `and` and multiplication of 0/1 indicators have the same local pair-joint relation; Boolean `or` and `indicator(add(a,b)>0)` have the same truth relation when `a,b` are Boolean. Comparisons `x>y` and `y<x`, and `x>=y` and `y<=x`, share an operator class after operand swap; `eq` is symmetric. No other comparison or algebraic rewrite is assumed.

For a complete per-item graph, the auditor evaluates all `2^k` Boolean assignments (`k<=4`) and stores the ordered integer contribution vector, together with aggregator kind and ordered role/dependency edges. This detects reordered commutative operands and equivalent Boolean notation without collapsing sum versus once-only count or shared-predicate topology. Full-program input/output equivalence alone **does not** imply that a higher-order signature was in training. Local pair motifs are exact two-predicate 0/1 conjunction subgraphs. Their presence is reported, never itself a freshness failure. The pair-joint motif is the **sole treatment-contrast exception** to both-condition coverage: its input predicates and typed atomic operations must be available in both, while the joint relation may occur only in COMPOSITION. No other missing atomic capability can be excused as treatment.

## 4. Task-semantic activity and source evidence

An extracted semantic node is active only if a deterministic counterfactual changes the correct output on at least one of the five frozen cases. For a predicate leaf, replace that leaf by false; for an integer constant, increment its value by one; for a pure operator, replace its result with its typed neutral or left child as specified in the auditor's closed mutation table; for a control/dataflow edge, remove that edge's contribution; for an aggregator, suppress one contributing item or one prior-state update. The auditor must record the case ID, original output and counterfactual output. A node with no witness fails activity and cannot contribute coverage. When two identical predicate occurrences share a semantic role, mutate **one occurrence at a time**; multiplicity is not silently erased.

Closed mutation table: `const(v)→const(v+1)`; `pred(P)→const(false)`; `neg(x)→x`; `not(x)→x`; `indicator(x)→0`; `add(x,y)→x`; `sub(x,y)→x`; `mul(x,y)→x`; `mod(x,y)→x`; `and(x,y)→x`; `or(x,y)→x`; each comparison `cmp(x,y)→not(cmp(x,y))`. For predicate definitions, apply the same table to each node and evaluate the enclosing task. `sum_per_item` loses the final item's contribution; `prefix_pair` uses zero prior count at every Q item; `product_of_counts` replaces the product by the sum of counts. A node's witness is the lexicographically first frozen case ID that changes output. If a required node has no witness, that task's case set is incomplete and the row fails; the auditor never calls dead syntax covered. Derived control/dataflow keys inherit the witness of the predicate/operator/aggregator nodes from which they were extracted, with the exact node path recorded. Repeated equal keys retain all occurrence paths and at least one witness per task-essential occurrence is required.

GOCO source must compile and agree with contract outputs on all cases. `INPUT` must feed the declared domain decoder; for the fixed numeric schema, the input variable must occur in the loop bound or a predicate. For the fixed array schema, the `INPUT` variable feeds `strings.SPLIT`, the resulting parts feed four `strings.TO_NUMBER` calls and the resulting values feed the array loop. This parser-chain certificate is extracted from GOCO source and is rejected if disconnected; a mere API token does not count. A construct or API appearing solely in source, with no corresponding active contract path, is `REFERENCE_ONLY` and supplies no coverage.

The source inventory is the v2 GOCO token tree plus a fixed scanner for declarations, `INPUT`, `LOOP`, `IF`, assignment/update, `DISPLAYNL`, array index, and imported library calls. The scanner records each occurrence and its source offset. A source occurrence can back an essential key only if the corresponding contract node is active and the compiler/case check passes. The numeric decoder certificate requires `INPUT(v)`, a `LOOP` whose header or condition uses `v`, and an output dependency on the loop accumulator; the array decoder certificate requires the exact import/split/four-conversion/array-iteration chain described above. Any unmatched source occurrence is emitted as `REFERENCE_ONLY` with proof code `EXTRA_SOURCE_ONLY`; this proof code is valid only for incidental identifier spellings, grouping, formatting, or demonstrably constant-false branches. Other unmatched occurrences require one of the explicit equivalence proofs below or the row fails.

## 5. TASK_ESSENTIAL versus REFERENCE_ONLY

`TASK_ESSENTIAL` is assigned only to active semantic contract requirements, domain decoder capabilities, required output categories, and fixed-schema input/output behavior. A canonical reference's variable names, grouping/formatting, and any extra source statements are `REFERENCE_ONLY`; they do not count as training capability evidence. For a nontrivial extra construct to be accepted as reference-only, the record must supply one of these frozen proof forms: (a) a syntax-preserving rewrite from the closed catalog above; (b) a compiler-checked alternative reference **plus** identical canonical contract graph, and exhaustive finite-domain equivalence when the domain is finite; or (c) a symbolic local proof from the closed identity catalog (`x+0=x`, `x*1=x`, constant-false branch removal, assignment desugaring `x+=y`↔`x=x+y`). Frozen-case agreement alone is not sufficient for an unbounded domain. If none applies, classification is unresolved and the audit fails. The auditor emits the proof code and evidence, not a discretionary waiver.

## 6. Fairness and freshness decision

For each evaluation `TASK_ESSENTIAL` key other than the pair-joint treatment relation, at least one source-backed, active training record in **ISOLATED** and one in **COMPOSITION** of the same domain must have an equivalent key and witness. The pair-joint relation is reported as treatment-asymmetric; it does not waive its component predicate, operator, control, or output requirements. Every source-only construct has a valid reference-only proof or causes failure. Every primary full signature must be absent in both conditions. Any uncovered requirement, dead-syntax-only purported coverage, missing case witness, prohibited full signature, unclassified source construct, or incomplete row is `FAIL`. Report each requirement and both evidence lists, category totals, and exact reason codes. There are no similarity thresholds, manual waivers, or post-candidate reclassifications.

The implementation and frozen synthetic fixtures must be independently reviewed before this method is used on attempt 004. Attempt 004 remains prohibited in the present task.
