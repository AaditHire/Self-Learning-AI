## 2. The construction function and closed input grammar

Define Recipe_v1(FrozenSlotSpecification) as a symbolic construction function. Its only inputs are the bound authorities, one validated ledger record, and ISOLATED or COMPOSITION only for a training record. It has no source, cases, model outcome, acceptance finding or implementation configuration input. Task/slot IDs are lookup/provenance fields, never dispatch predicates.

A specification has exactly: authority_binding, population_kind, slot_identity, family, frozen_record, condition. The binding identifies every authority above; population_kind is TRAINING, PRIMARY, PRIMITIVE_SANITY or STRUCTURAL_TRANSFER. Family is numeric_iteration or array_reduction. Condition is null for evaluation and one of the two frozen conditions for training. frozen_record has EXACTLY its ledger group's existing fields; validate its full equality to the selected bound ledger record, rather than allowing a caller to supply “equivalent” fields. Reject unknown, omitted, duplicate or altered fields/roles. A record's variant is provenance, not permission to choose another function.

Construction has these fixed stages: validate binding/record; choose the closed semantic term and required role set; lower domain and phases; lower only referenced predicates; lower state/term/output; attach fixed scientific facts; assign positive essentiality and exhaustive selector/support classification; derive direct prerequisites; assign occurrence and requirement identities; serialize. Any undefined operation, role, attachment, classification, prerequisite owner or intervention destination is a rejecting construction, never an implementation-default choice.

The closed symbolic grammar is:
- values: decoded numeric n, four decoded signed array values, original current index, exact integer constants, and named state views;
- the eight named predicate definitions in §8;
- pure operators neg, add, sub, mul, mod, eq, lt, le, and, or, and BOOL_TO_INT;
- bounded traversal, IF choice, indexing, declaration/binding, initialization, assignment/update and final integer display;
- sum_per_item, strict-prior prefix_pair, and completed product_of_counts, expanded by §§11–15, never graph macros.

Divisor evaluation is permitted only at valid numeric indices 1..n. Types are INT, BOOL, INDICATOR_INT (integer 0/1), TEXT, TEXT4, INT4 and UNIT. INT retains the frozen language/compiler's integer semantics; no new precision, overflow or division convention is supplied. Future compiler/reference incompatibility is FAIL/UNRESOLVED, not a rewritten predicate.

## 4. Closed EDGE model and constructive emission table

An EDGE has EXACTLY:

    edge_id, construction_clause, occurrence_path, edge_type, source_node_id,
    source_port, target_node_id, target_port, value_type, source_role,
    target_role, state_id, phase_id, attachment_ids, ordering_key,
    task_essential, selector_class

Ports/endpoints resolve to exact typed occurrences; parallel edges retain separate occurrence_path values. Closed pure operators use input ports arg0, arg1 in the term's full operand order (NEG and BOOL_TO_INT use only arg0) and one result port. A writer's prior/contribution roles refer to arg0/arg1 before any allowed pure child sort; an attachment preserves the role through that sort. Named predicate argument ports follow the runtime dependency order in §8, followed by constant-parameter roles in their left-to-right tree occurrence order; internal operators retain their own actual operand ports. INPUT has no input port; SPLIT uses text then delimiter and field-result ports field0..field3; TO_NUMBER uses its one field; INDEX_READ uses package then index. Control uses decision, writers use assignment/contribution as appropriate, views use value, and display uses integer_result. State views and package fields carry types even where an association is an attachment rather than an EDGE. The port order is the listed order, not alphabetic or source order; unknown ports reject. The edge category for capability classification is ATOMIC_CONTROL_DATAFLOW. Emit an edge only by the following direct construction clauses, never by generic transitive reachability:

| Edge type | Emit when |
|---|---|
| INPUT_TO_DECODER | A frozen input/field result supplies INPUT/SPLIT/TO_NUMBER in the domain decoder; preserve each of four field→conversion ports |
| VALUE_TO_PREDICATE | An actual domain/index/value/threshold binding is a formal dependency of the named frozen predicate; retain its exact argument role |
| PREDICATE_TO_CONTROL | Predicate Boolean or loop decision supplies the particular required IF/body-control decision |
| PREDICATE_TO_INDICATOR | Predicate Boolean supplies its required 0/1 indicator realization; control and indicator uses are distinct records |
| VALUE_TO_OPERATOR | A typed runtime/constant/operator result supplies one operand of a closed expression operator, including index/bound operations; preserve both ports of repeated operands |
| OPERATOR_TO_ACCUMULATOR | A required numeric contribution producer supplies one specified accumulator-update contribution port; record the writer, prior state and contribution separately |
| CONTROL_TO_UPDATE | A required loop/IF decision guards one particular initialization/assignment/accumulator writer |
| LOOP_CARRY | The post-iteration value of a specified state is the next iteration's pre-state in that same traversal |
| PRIOR_STATE_TO_UPDATE | A specified pre-state is the prior operand of that state's update writer; it is not interchangeable with post-state |
| ACCUMULATOR_TO_OUTPUT | The completed result state supplies the actual final integer display, after all required computation completes |

An argument already represented as PRIOR_STATE_TO_UPDATE at the same writer/prior port is not also emitted as VALUE_TO_OPERATOR merely to duplicate its data dependency. Different semantic relations, such as a prior count supplying a separate contribution multiplication, still receive their own VALUE_TO_OPERATOR edge.

Initialization association, expression-root/result association, predicate-definition ownership, completion, phase membership and completed-state persistence are attachments/ordered state facts. They are not invented ontology edges. OPERATOR_TO_ACCUMULATOR denotes one actual contribution into one writer, not an arbitrary multi-step output dependency; its typed state/update association must be reconstructed. No PHASE_BOUNDARY, STATE_READ, PREFIX, TWO_PASS, traversal or recurrence edge exists. All ten listed types remain available; no task is padded to instantiate a type it does not require.

## 9. Boolean, indicator and control distinctions

A predicate result is BOOL; BOOL_TO_INT maps false→0, true→1 and has INDICATOR_INT result. IF_CHOICE consumes BOOL and controls a particular writer. A PREDICATE_TO_CONTROL edge records that decision use; PREDICATE_TO_INDICATOR records Boolean-to-0/1 realization. They are not the same edge and cannot discharge each other's selectors.

Training retains the frozen two-IF indicator assignment scaffold: indicators initialized/reset to 0; P's first IF sets its indicator to 1; Q's second IF independently sets its indicator to 1. The resulting indicator semantic role and actual conditional writer are explicitly paired, retaining BOTH control and indicator facts. Logical BOOL_TO_INT describes that indicator's value, not a second executed conversion or permission to omit either IF.

For every other I(Boolean term) used in §§12–15, the fixed I-CONVERT clause emits one per-item ephemeral indicator with reset=0, one IF_CHOICE on that exact Boolean producer setting it to 1, its BOOL_TO_INT numeric result view, PREDICATE_TO_CONTROL, PREDICATE_TO_INDICATOR, and CONTROL_TO_UPDATE at that writer. The reset/set constants and storage are attached under §16. This is one 0/1 realization, not a second executed conversion call; no carry links the ephemeral indicator across items. Training reuses its already mandated indicator scaffold rather than adding another conversion. Source must realize these same roles or supply an already permitted exact typed correspondence; output agreement does not authorize a general IF-to-indicator equivalence or a different control topology.

The frozen local-pair AND/0–1 multiplication and Boolean-OR/positive-indicator rules require their exact type/purity/source-mapping certificates. Neither turns a whole G1–G4 or structural recurrence into one atomic relation or authorizes collapsing control into dataflow.

It denotes one logical traversal only. The stage-role vocabulary is entry, item.read, item.predicate, item.contribution, item.result_update, item.other_update, item.index_step, completion. Groups have clause-specified membership and ordering, not a universal requirement that every predicate run before every conditional writer; unused groups are absent, never dummy execution. A clause can emit successive distinct groups with the same stage_role and different stage_occurrence_path. In training, this explicitly preserves P evaluation/IF/assignment before Q evaluation/IF/assignment as separate predicate/update groups, followed by treatment contribution and total update. PREFIX retains its permitted pure-truth group and required result-update-before-P-count-update order. TWO_PASS keeps the two complete phase sequences and the final product's after-both-completions ORDER_RELATION outside any third traversal. Within a group, absent scientific ordering is recorded as unordered, not invented from node serialization. Required ordering between groups is retained. Initialization/reset/writer operations at the same group are ordered only where the owning frozen scaffold says so.

State roles are INDEX, INDICATOR(role or Boolean-term path), TOTAL, PRIOR_P_COUNT, P_COUNT, Q_COUNT and FINAL_RESULT. Ephemeral indicator realization state is not another carried aggregation/count state. Domain roles are RAW_INPUT, DECODED_N, FIELD(position), ELEMENTS, ORIGINAL_INDEX, DOMAIN_BOUND and DOMAIN_STEP. Positions are clause-generated integers; no arbitrary caller labels are accepted.

1. initial value attachment and INITIAL view at its specified entry;
2. PRE view for the current item;
3. numeric ADD writer with exact prior and contribution ports;
4. PRIOR_STATE_TO_UPDATE from PRE to the writer's prior port;
5. OPERATOR_TO_ACCUMULATOR from the term's numeric producer to the state's write/contribution role, with the exact ADD writer association;
6. POST view defined by that writer, and LOOP_CARRY POST→next PRE;
7. COMPLETED view at domain completion and its exact final consumer.

The writer ADD's contribution operand is also represented by VALUE_TO_OPERATOR from the numeric producer to its contribution port. This one arithmetic operand relation and the accumulator-contribution relation have different scientific roles and endpoints; neither is invented as an output dependency. The writer-to-state definition is an attachment, not an extra edge label.

OPERATOR_TO_ACCUMULATOR suppression suppresses the specified *contribution*, retaining prior state; it does not replace the entire accumulated next value by zero. Numeric ADD-node or PRIOR_STATE_TO_UPDATE interventions use the frozen 0/1 destination replacement instead. These are separate existing intervention classes.

For a Boolean/count term, its producer is BOOL_TO_INT with 0/1 result. Required conditional writers receive CONTROL_TO_UPDATE from their actual IF decision; each body writer receives the relevant loop-control association. INITIALIZE/ASSIGN/binding carriers retain their source roles without inventing separate operator keys for storage syntax. An index update emits its real ADD/SUB operator and the index's carry/prior dependencies; it is not an accumulator contribution merely because it uses arithmetic. Indicator states are reset per item and do NOT receive inter-item accumulation carry. Their frozen outer declaration initialization and item reset are distinct occurrences.

Completed state uses the same state_id as its live recurrence. Phase persistence is recorded as a state's persisted interval and a consumer attachment linking completed source phase and later consumption. No cross-pass LOOP_CARRY or new PHASE_BOUNDARY edge is invented. A view's INITIAL/PRE/POST/COMPLETED role cannot be substituted by another view of the same numeric type.

## 14. PREFIX construction from the joint freeze

ST-PREFIX emits exactly one forward logical domain traversal; PRIOR_P_COUNT and TOTAL are distinct INT states initialized to 0 before traversal. P/Q use the exact frozen role entries; R/S are metadata.

For each item template:
- bind PRIOR_P_COUNT.PRE and TOTAL.PRE separately;
- compute the current P and Q Boolean truths with their predicate definitions; their pure evaluation group has the joint pair's qualified ordering freedom;
- compute contribution = MUL(I(Q), PRIOR_P_COUNT.PRE);
- update TOTAL = ADD(TOTAL.PRE, contribution);
- only afterward update PRIOR_P_COUNT = ADD(PRIOR_P_COUNT.PRE, I(P));
- carry both respective POST states to their own next PRE states;
- after completion display TOTAL.COMPLETED, never the prior-P count or an intermediate result.

Use U-SUM independently for each state, preserving their distinct writer/contribution/carry ports. The MUL's prior-count operand is a VALUE_TO_OPERATOR with PRE attachment; the prior operand of the P-count writer is PRIOR_STATE_TO_UPDATE. A completed or POST prior count cannot satisfy the MUL operand selector. The ordered groups result_update then other_update are required scientific content, not serialization.

The completed function is the strict ordered-pair sum Σ_i Q_i Σ_{j<i} P_j. Numeric empty traversal preserves both zeros and one logical traversal/completion. No empty array is admitted. Inclusive state, existence flags, full-prefix recomputation, separate prior P pass or closed-form precomputation cannot match this graph even if some outputs agree. No macro capability or macro edge is constructed.

## 15. TWO_PASS construction from the joint freeze

ST-TWO emits exactly two forward complete domain traversals.

Phase 0: P_COUNT initialized to 0 at its entry; compute P/I(P), use U-SUM for the P count only, carry within that traversal, and record P_COUNT.COMPLETED. No Q aggregation occurs.

Boundary: P_COUNT.COMPLETED persists unchanged. Its initialization, completion and the interval through the second phase remain explicit state attachments. It has no first-traversal Q-state alias and no subsequent P writer.

Phase 1 entry: initialize a distinct Q_COUNT to 0, now and not at Phase-0 entry. Compute Q/I(Q), use U-SUM for Q only, carry within that traversal, and record Q_COUNT.COMPLETED over the same ordered domain.

After BOTH completions: MUL consumes the two completed count views at separate ports; its result carrier FINAL_RESULT supplies the final display. This final expression stage is not a third traversal. VALUE_TO_OPERATOR endpoints bind the exact completed states; output association retains the final expression/result role rather than inserting an extra result accumulation or loop.

Phase records carry ordinal 0/1 and the exact P-first/Q-second role memberships. P's persistence is completion/consumer metadata, not a new edge. The complete function remains (ΣP_i)(ΣQ_i), with same-item combinations included. Numeric n=0 still has both logical phases, their completion boundary, two zero initializations and final product.

No one-loop simultaneous count graph, phase reversal/fusion, interleaved counts or partial product matches this topology. Commutative sorting of the final MUL ports does not reverse traversal order or erase which completed count each port names. Early source Q storage declaration is not a Phase-2 initialization certificate: future mapping must identify the actual logical initialization writer at Phase-2 entry, and prove the exact lifetime/definition facts, or fail. The frozen IMPLEMENTATION_ALIGNMENT_FOLLOW_ON status remains; this proposal neither adapts to current source nor certifies it.

## 23. Static multiplicity, use identity and runtime repetition

Multiplicity is static canonical occurrence multiplicity, independent of capability identity and runtime iteration counts. Rules:
- each required predicate producer is one per used role per traversal; each actual term/operand use has its own edge and occurrence position;
- one shared predicate supplying two or three roles has one producer and two or three independently attached uses;
- each repeated operator occurrence in the frozen binary term is distinct, even with equal operation/type/key;
