## Exact frozen decision rules

- **Pre-B A hard STOP:** each of seeds `20260925`, `20261013`, `20261119` must individually pass `>=24/32` A tasks overall, `>=10/16` in *each* A subskill, and `>=2/8` in *each* of four A archetypes. A task PASS means all five hidden semantic cases pass. If **any** seed misses **any** floor, publish the pre-B result, mark `STOP_before_B_no_tuning`, and run **no B training**. No added A epochs, replacement seed, hyperparameter/prompt changes, checkpoint search, or rerun to pass.
- **H1 exact acquired-task retention:** for seed `s`, let `P_s` be the A task IDs that PASS immediately before B. For branch `c`, `R_s,c = count{t in P_s: post-B c PASS(t)} / |P_s|`; forgetting is the complementary `PASS→FAIL / |P_s|`. The same `P_s` is used for both branches. The primary effect is the **macro-average** `(1/3) Σ_s (R_s,replay − R_s,naive)`, **not** pooled eligible seed-task outcomes. H1 requires effect `>=0.20` (20 percentage points) **and** `R_s,replay >=0.50` for every seed. Report all four paired transitions, including `FAIL→PASS`.
- **H2 aggregate A:** for each seed/branch, hidden-test pass@1 is `post-B PASS count / 32` across all frozen EVAL_A tasks. H2 requires `(1/3) Σ_s (postA_s,replay − postA_s,naive) >=0.10` (10 percentage points). H1 and H2 are conjunctive.
- **Naive B broad-acquisition eligibility:** in **every seed**, post-naive-B minus pre-B B PASS counts must be `>=12/32` overall, `>=4/16` in **each** B subskill, and `>=2/8` in **each** of four B archetypes. These are *net pass-count gains*, not gross `FAIL→PASS` counts. If any floor fails, report B data but forbid a claim that replay preserved **broad B plasticity**; the joint experiment is FAIL after complete B results.
- **H3 replay B:** only after the naive gate passes, replay's unweighted three-seed mean B **net gain from pre-B** must be `>=0.75 ×` naive's mean net gain; replay must have **positive** net B gain in each B subskill in **every seed**; and every seed's replay post-B overall B PASS count must be no more than **9/32 below** the matched naive count. Broad plasticity claims require the naive gate and H3 together.
- **H4 non-GOCO:** use the unchanged 64-item suite at base, post-A, post-naive-B, post-replay-B. For each seed, a severe collapse is **strictly more than 9/64** items below the single base score for **any** of post-A, naive, replay, or strictly more than 9/64 for replay below its **seed-matched naive** score. A drop of exactly 9 does not cross the boundary. H4 passes only if no seed collapses.
- **Joint:** PASS requires eligible A acquisition plus H1, H2, H3 (including broad naive B eligibility), and H4. Complete B-stage data failing any gate is FAIL. Pre-B ineligibility, corrupt/missing provenance, compute/schedule mismatch, evaluator defect, or incomplete results are STOP without imputing PASS/FAIL.

Seeds are fixed and equally weighted, never resampled or pooled as 96 independent observations. Unequal acquired-A denominators are handled by calculating each seed's retention ratio first and then averaging the three matched differences, as in H1 above. Pre-B ineligible seeds stop the experiment before B, so no H1/H2 estimate is produced for that execution.

Use descriptive percentile **2.5th/97.5th** intervals for H1 and H2. Independently resample 32 B task IDs for descriptive intervals on naive and replay net gain and their difference. Resample 64 non-GOCO item IDs for paired differences. Report four A and four B archetype-specific effects plus a **four-whole-archetype-block** bootstrap sensitivity; its intervals are explicitly unstable. Intervals never change deterministic gates.

## Evaluation/training separation and matched compute

`train_eval_separation.json` is machine-generated from the frozen data and schedule: 60 A-training IDs, 60 B-training IDs, 64 evaluation IDs, 108 A-replay slots across all seeds, **zero** replay IDs outside A training, **zero** evaluation IDs in any replay schedule, **zero** exact evaluation prompts or reference programs in replay training targets. The construction is static: pre-B outcomes enter only the all-seed eligibility gate, never the replay-ID list, replacements, training targets, or schedule. The training script constructs its `TokenDataset` solely from the two frozen training JSON files; no evaluation reference, hidden test, failure, or generated repair is a training row. The frozen data audit separately records zero exact prompt reuse and zero `>=0.98` normalized-code rejects.

Before loading a model, execution verifies the frozen config, 26 input content hashes, compiler hash, model support/tokenizer hashes, base-weight hashes, and all nine seed/epoch schedules. Each B branch has **180 exposure slots**, **24 optimizer steps**, micro batch 1, accumulation 8, and the same final-epoch checkpoint rule. Per epoch, naive has 60 B slots; replay replaces exactly six string and six field B positions with six numeric and six array A training examples. Replay therefore has 48 B + 12 A slots per epoch (20%), 36 unique A IDs per seed, with the remaining B order identical. Both branch entry points check the every-seed A gate, exact parent A adapter file hashes, LoRA settings, and fresh optimizer/scheduler policy. The second branch also compares its parent and trainable-parameter count to the first branch's record. No extra replay steps are scheduled.
