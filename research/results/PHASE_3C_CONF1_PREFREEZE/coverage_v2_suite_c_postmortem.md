## Shared first-principles witness analysis

For numeric tasks, the five stdin values are `0,4,8,12,20`. Predicates are `A: i%4==0`, `B: 3*i<=n`, and `C: i%5==0`. Their true-item counts by case are respectively `A=[0,1,2,3,5]`, `B=[0,1,2,4,6]`, and `C=[0,0,1,2,4]`. These counts show branch activation, but activity also requires a changed **output** under the frozen node mutation. In every isolated `A+B` or `A+C` task, and in the corresponding evaluation tasks, changing A's equality constant `0→1` leaves all five outputs unchanged. `C_COMP_AB` has final-item contribution zero on every case, so suppressing the final item also leaves every output unchanged. `C_COMP_AC` has an active final item at `n=20`, but changing C's equality constant `0→1` leaves all five outputs unchanged. Other constants have witnesses as listed in the saved one-run failures and checked by a separate direct contract calculation.

For array tasks, the five live inputs are `0|0|0|0`, `-2|0|0|0`, `-2|-3|0|0`, `1|2|3|0`, `0|0|0|-2`, giving outputs `0,1,2,0,1`. The branch `value<=-2` is true on the negative entries. Changing the required predicate constant `-2→-1` changes **none** of these outputs, since no case contains `-1`. The last live input witnesses the final-item accumulator effect. The dead-array fixture instead ends with `0|0|0|5→0`; its fourth conversion is absent from the iterated array, and its final-item suppression also has no output effect.

For the negative-initial numeric group, outputs are `C_ISO_AB=[-2,0,2,5,9]`, `C_ISO_AC=[-2,-1,1,3,7]`, `C_COMP_AB=[-2,-2,-2,-1,-1]`, and `C_COMP_AC=[-2,-2,-2,-2,-1]`. The computed initial `0-2` and negative output category are witnessed. `C_COMP_AB` still lacks a final-item witness; `C_ISO_AB` and `C_ISO_AC` still lack the A equality-constant witness. The evaluation's literal `-2` is source-active, but neither training condition contains that exact lexeme.

All numeric contracts require the source-backed numeric decoder (`INPUT` into a bounded loop), predicate and operator nodes, active conditional accumulation, loop carry, accumulator-to-display, computed constant roles, and witnessed output categories. Array contracts additionally require `strings.SPLIT`, four connected `strings.TO_NUMBER` results, indexed array iteration, and an active value predicate. A single inactive required node invalidates the row; an invalid training row supplies no positive capability evidence. Primary full-signature absence is an additional unconditional requirement.

## Confirmed implementation defect

The auditor computes each training full signature, then skips storing it when any other row failure exists. The frozen rule requires a primary full signature to be absent from **both training sets** and requires every violated requirement's reason to be emitted. `C_FULL_TEMPLATE` and `C_COMP_AB` have the same typed signature; their incomplete activity witnesses do not make that signature absent. The minimal repair is to collect the training signature before skipping the row for positive capability coverage. This leaves invalid training rows excluded from positive evidence while reporting the independent prohibition.
