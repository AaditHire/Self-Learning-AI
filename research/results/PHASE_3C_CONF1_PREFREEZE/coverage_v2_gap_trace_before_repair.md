# Coverage v2 rule-to-code gap trace, before repair

This trace was written before editing the frozen auditor implementation. It maps the four independently reviewed gaps to the unchanged normative rule and current code. It uses no attempt-004 or model output.

| Gap | Normative rule | Current implementation stopping point |
|---|---|---|
| Array parser/dataflow chain | Section 4 requires `INPUT → strings.SPLIT → four strings.TO_NUMBER results → iterated array value → predicate/operator → accumulator → DISPLAYNL`, with source-backed activity. | `_source_certificate` matches `INPUT`, a `strings.SPLIT(input_var, "|")` assignment, four textual `strings.TO_NUMBER(parts[k])` occurrences, and any `NUMBER[]` declaration. It never binds the conversion targets to the array initializer, the array to a loop index, the indexed value to an active predicate, or the accumulator to `DISPLAYNL`. `extract` then emits all three API capabilities unconditionally when `domain=array_reduction`, given the partial certificate and compiler/case agreement. |
| Numeric loop condition | Section 4 requires the parsed loop variable, initialization, condition, update and bound dependency. | `_source_certificate` finds the first textual `LOOP (` and searches the next 140 source characters for the input variable name. It does not parse the header or distinguish a condition from a body/comment. `extract` emits `BOUNDED_ITERATION` independently of loop-header structure. |
| Unmatched source constructs | Sections 2, 4 and 5 require each encountered source/AST construct to be classified as task-essential, proven reference-only, or unresolved failure. | `_source_certificate` only counts IF occurrences against predicate occurrences plus graph condition nodes and recognizes a constant-false surplus IF; it also recognizes a `NUMBER name=` declaration whose name occurs once. It does not enumerate all parsed statements, expressions, calls, loops, assignments, or output constructs, and unmatched forms can leave no `reference_only` or failure record. `extract` emits `NUMERIC_ASSIGNMENT_UPDATE` without verifying an active source update. |
| Full structural signature | Sections 2 and 3 require contribution vector **plus** typed predicate/operator/accumulator/output nodes, directed edge types, multiplicity, shared-predicate relationships and aggregation topology. | `_full_signature` returns JSON `["sum_per_item", sorted_predicate_names, truth_vector, canonical_initial]` (or `[aggregate_kind, names, p, q]`). No typed edge list, source/target identity, edge multiplicity, or explicit predicate-sharing graph is serialized. Thus two graphs with equal vectors and node inventory but different typed edges can collide. |

The current v2 lexical token tree is only used in the separate AST-overlap tool; `_source_certificate` does not use it for loop or parser-chain dataflow. The repair must use a parsed supported GOCO subset and fail closed on unsupported constructs. The frozen coverage-v2 rule and Suite A labels/results remain unchanged.
