# Phase 3C-DEV2R Structural Transfer construct essentiality

**Decision for independent review: 16/16 task-essential construct coverage, with the frozen reference-construct gate still 0/16.** No protocol, scientific input, adapter, or execution code was changed. DEV2R remains blocked and unauthorized for model execution.

The earlier source-coverage audit correctly found that every frozen Structural Transfer reference initializes `anchor=-1` and neither original DEV2 training condition contains a negative integer literal in its target/reference programs. The reference uses `-1` solely as an **absent-anchor sentinel**: a matching nonnegative index replaces it, and `anchor>=0` guards counting when no match exists. The task specifications ask for an offset count, including zero qualifying positions when no anchor exists. None asks to print `-1`.

To separate reference choice from task requirement, [the diagnostic audit](essentiality_audit.json) constructs one independent program for each frozen Structural Transfer task. For suffix-after-first tasks, a forward scan counts the second predicate only after an earlier first-predicate hit. For prefix-through-last tasks, a reverse scan encounters the last first-predicate hit first, then counts the second predicate from that position downward. Both use a nonnegative `seen` count initialized to zero. No negative literal, unary negation, absent-anchor sentinel, or direct index assignment is used. The programs use the same two frozen semantic predicates, same input API, and GOCO constructs present in **both same-family** original training conditions. The original references and hidden cases were not modified.

All **16 diagnostic alternatives passed 5/5 existing frozen semantic cases** with the pinned compiler: **80/80 case passes**. The per-task artifact includes each alternative source, its construct inventory, coverage in both conditions, compiler-case outcomes, source/input hashes, and justification. This is evidence that the negative literal is a reference-only gap for these frozen tasks. It does not show that any adapter can learn or produce the alternative, and five cases cannot prove general correctness for every possible input. The scan algorithms also support the specified behavior for arbitrary valid inputs by construction: the `seen` count changes from zero exactly when an anchor satisfying the first predicate has been visited in the relevant traversal direction.

Every individual task ID and classification appears in the machine-readable audit. Numeric tasks have nonnegative input `n`, so no negative-value handling is required. Array tasks may receive negative values: the `negative_value` predicate compares to the covered literal zero, and `large_magnitude` squares entries; both operations and primitives occur in both original same-family training conditions. The frozen spelling `-1` might be parsed as a signed literal or unary minus by the compiler; the alternative avoids either form. No separate negative-value arithmetic is introduced by the sentinel-free algorithm.

**Recommended treatment:** independent review may consider a prospective protocol amendment that distinguishes *task-essential* construct coverage from incidental reference-program literals. The previous frozen gate must not be silently reinterpreted; the original 0/16 reference-construct result remains valid. The Primitive Sanity group's separate `-1` output requirement was outside this Structural Transfer audit and remains to be assessed before claiming full-suite fairness. The known runner authorization inversion and missing exact-target own-training diagnostic also remain unrepaired. The DEV2R manifest still has `model_execution_authorized: false`; no DEV2R model evaluation or gradient execution occurred.
