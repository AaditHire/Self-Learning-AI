## Adapter and evidence result

The new path derives a typed grammatical requirement plan from declarations
before parsing a realization. Selectors address grammatical sites and typed
capabilities, not development case IDs or source-derived raw occurrence IDs.
The adapter then binds every grouped requirement to parsed source occurrences
and returns a serialized certificate. The reference realization is independently
required to match the prospective grammar under a complete typed binding map.
No before/after plan changes or caller-supplied PASS classifications are accepted.

Each binding records exact requirement/key identity, capability, role and
type/domain, evidence kind, multiplicity, contract/source occurrences, direct
typed or authorized V3.3 mapping mode, evidence identity, source locations and
bindings, control/state context, dependency edges, and unresolved reason.
Successful complete bindings have `unresolved_reason: null`; an unbindable
projection raises a fail-closed reason rather than emitting a partial PASS.

There are 107 verified mapping records: 47 direct, 47 alpha-renamed, nine other
typed equivalence examples, and four regional Boolean transports. The production
adapter has no case-ID dispatch. The resolver, typed accounting, and equivalence
kernels are structurally reusable; accepting actual scientific contracts or
materializing slot-specific sources still requires separately authorized work.
This new declaration/plan format is development evidence, not a replacement for
the frozen scientific CoverageContractV3/requirement interfaces.
