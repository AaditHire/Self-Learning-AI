## Frozen-authorized policies and completeness

| Capability behavior | Authorized intervention order |
| --- | --- |
| Boolean primitive/operator or branch/loop decision | FALSE, then TRUE |
| Numeric operator or directed numeric value edge | Result at destination 0, then 1 |
| Numeric API decoder/index result | 0, then 1 |
| SPLIT | Four string zero fields, then four string one fields |

type, semantic role, complete source mapping and required computation constrain

repaired. The catalog records authorization, types, joint scope, soundness,
unsafe conditions and unsupported reasons.

independently reconstructs its canonical atomic key and expands intervention
to every identically typed instance in the complete mapped graph, retaining
repetitions and both indicator-check and inline-Boolean occurrences. A live
required-computation representative is mandatory; a source-only unused key
cannot supply activity. Dead instances of the same key remain distinguishable
in the complete joint set. No different operation, type, role, loop/pass key or
unmatched source behavior is absorbed into that set.

## Evidence, events and derived statuses

Every case is bound to a verified development mapping, state graph and required
computation. Normal execution succeeds and agrees with the hash-pinned GOCO
compiler. The same original raw input is supplied to both executions; an INPUT
intervention changes only its frozen-authorized IR destination adapter, not
the declared case identity. There are no source-text mutation interventions.

Normal evidence requires an actually evaluated mapped path and a nonzero
displayed-accumulator contribution / selected nonzero update with the key in
its ancestry. Intermediate two-pass counts alone cannot certify a product
whose normal displayed contribution is zero. A false predicate merely masked
by another OR operand supplies no positive selection event. Numeric empty-loop
cases do not prove decoder activity.

ACTIVE requires this normal event, a typed authorized complete intervention,
valid terminating counterfactual state and the required final-output change.
The first changing intervention in frozen order and lexicographically first
ACTIVE case are recorded explicitly. INACTIVE requires intended-case exposure,
all listed interventions valid and terminating, and no output change. It is
case-local, never a proof of global inactivity. A redundant OR projection with
true negative/even paths supplies real INACTIVE witnesses; the same capability
has an ACTIVE witness on another development case.

Dead/unsuitable cases return `UNRESOLVED` /
`NO_ACTIVITY_EVIDENCE_ON_THIS_CASE`, not `CAPABILITY_PROVED_INACTIVE`.
Unsupported policies and unverifiable counterfactuals also remain UNRESOLVED.
Case-set findings are limited to the explicitly declared development cases;
they do not establish scientific V3.5 closure. Caller ACTIVE, output_changed,
safe_intervention, event or REFERENCE_ONLY flags cannot create evidence.

Normal/counterfactual records retain events, outputs, evaluated occurrences,
full joint inventories, intervention before/after values, affected bindings,
actual readers/writers, verified temporal edges, loop/pass/iteration context,
initial state and output ancestry. The runtime `values` inventory logs local
results before destination replacement; INTERVENTION records and subsequent
state/events retain the actual replaced values. That distinction is explicit,
not an assertion that pre-replacement values are counterfactual final values.
